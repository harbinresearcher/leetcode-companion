## 已发现的规格缺口

1. `JSON.stringify` 会把 `fsrsCard.due`、`last_review` 从 Date 变成字符串。解析后必须恢复 Date，否则题库的 `toLocaleString` 与 Date 到期索引不再可靠。恢复类型不是重新调度；due/reps/stability 等值不得变化。
2. 附录只要求 fsrsCard 为非 null 对象，但 `{}` 和数组不能构成可用 Card；aiAnalysis 只校验外层也不足以保证 warnings/prerequisites 可读取。需要核心会话给出实际类型与最小反例，再由总架构确认补充校验，不能盲目把对象强转成 Problem。
3. 预览时的 existingIds 可能在提交前过期。另一个标签页新增或删除题目后，不应在“只新增”下覆盖新数据，或将写入失败报告成成功。先用回归测试确定行为，事务中的最终判定方案交总架构确认；签名保持不变。
4. buildBackup 的白名单应覆盖内嵌对象：直接引用 aiAnalysis/fsrsCard 会把它们后来夹带的未知字段带出。按当前合法类型字段逐项导出，API Key 与未知敏感字段不能被备份。

前两项影响恢复后可用性，第三项影响用户数据，属于集成验收关注点。核心会话可先完成无歧义的导出和测试，不应因为缺口自行扩展迁移、云同步或设置备份。
