# 第一阶段实现与验收路线

用户已授权自动判断方案并开始开发，不重复请求设计审批。

## 设计

保留原方案范围、React 18、三个 Tab 和 AI 设置。采用简单 src 文件结构，不引入后端或全局状态库。深色工作台使用石墨底色、暖金色操作强调、系统中文字体和等宽代码字体；导入页左侧输入、右侧学习路径和固定模式，移动端单列。

## 修正原方案

- 初版验证使用 Tailwind 3。实际 npm audit 发现其 braces 依赖无已发布修复版本，最终改用 Tailwind 4 的 Vite 插件，移除旧 PostCSS 配置；同时升级 Vitest 5，保留 React 18。
- 不将非法模式静默标成双指针。使用固定模式作为结构兜底，并明确展示分类待确认提示。
- JSON 无法解析时拒绝导入；可解析但字段缺失时校验默认值并显示警告。
- 对 API 响应结构、超时、HTTP 错误和浏览器网络失败提供可见错误，不输出密钥或原始服务端错误正文。
- 默认保持 TypeScript 骨架，和初版 Prompt 一致；不额外增加语言切换。
- IndexedDB 添加 fsrsCard.due 索引，用 Date 查询到期卡片。
- 复习题干完整展示，答案和模式在揭示前隐藏；保存评分后才移出队列，使用事务防止过期快照重复评分。
- 固定当前会话队列；Again 到期后可重新加载，不自行修改 FSRS 的分钟学习步骤。
- 暂不做导出功能。README 明确尚无导出，避免提示用户使用不存在的功能。

## 路线

1. 核心：先写 AI 校验、API 失败、Date 持久化和评分一致性测试，观察失败，再实现。
2. 界面：导入、题库、复习、AI 设置；验证正常流程和错误恢复，桌面与移动尺寸。
3. 交付：运行测试、构建、浏览器验证与截图，更新 README 和交接记录，提交推送。

真实 AI 验收需要用户自己的 Key。本轮不寻找或读取用户已有密钥，使用隔离浏览器中的请求替身验证闭环，并如实标注。

## 最终验证

React 18 与 16 个批准模式均保持不变。Tailwind 最终使用 4.3.3+，Vitest 使用 5.0.3+，锁定版本见 package-lock.json。12 项核心测试、构建、生产预览与开发服务器的浏览器闭环已通过，截图使用隔离浏览器的模拟 AI 响应。真实 AI 分类仍待用户配置自己的 Key 验收。

本机受限环境只在 node_modules 中临时替换 esbuild 为 WASM 版本，未改变提交依赖。最终 npm audit 为零已知漏洞。测试工具缓存不提交。
